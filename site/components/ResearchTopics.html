Typically web developers use a web framework for developing their applications. Your task would be to figure out what is the state of frameworkless web application development and understand how far you could go by relying on the platform and a few well selected libraries. [No.JS](https://no-js.dev/) lets developers express application behavior through HTML attributes interpreted by a JavaScript runtime in the browser. Your task would be to survey this approach and compare it with [Datastar](https://data-star.dev/) and related tools such as [htmx](https://htmx.org/). Examine where state and rendering live, how data moves between the browser and server, and which interactions require custom JavaScript. The topic could remain a survey or expand into an empirical study by implementing the same small application with a selected set of tools. Possible measurements include initial transfer size, interaction latency, network traffic, and browser and server resource use under comparable workloads. Assess implementation complexity and limitations alongside performance. Solutions like [Nordcraft](https://nordcraft.com/) promise a new way to develop web applications with a minimal amount of coding effort. Your task is to investigate several solutions like this and then come up with a view of the functionality and challenges of the existing tools. You can bring your own point of view to the topic. Your task is to figure out the potential impact of the new legislation while understanding the current state of accessibility within the industry. A [report on specification engineering](https://drops.dagstuhl.de/storage/04dagstuhl-reports/volume15/issue09/25392/html/DagRep.15.9.160/DagRep.15.9.160.html) describes semantic errors and ontology drift in LLM-generated specifications. Your task would be to investigate whether defining a domain ontology early can reduce such drift in agentic software development. Make the domain's concepts, relationships, and constraints explicit, then use this ontology to guide agents producing specifications, code, and tests. Develop a prototype workflow that traces these artifacts to the ontology and checks their consistency. Compare it with specification-driven development on the same requirements and change tasks. Evaluate unintended changes in domain meaning, inconsistencies between artifacts, functional correctness, and human correction effort against independently reviewed requirements. Include the effort needed to create and maintain the ontology, and distinguish semantic drift from intentional requirements changes. [ReScript](https://rescript-lang.org/) is a statically typed language that compiles to JavaScript, while [Datastar](https://data-star.dev/) enables reactive interfaces through HTML attributes and backend updates. Your task would be to investigate the feasibility of combining the two for web application development. Build a small prototype and evaluate integration effort, type safety across the client-server boundary, developer experience, and limitations. The aim is to understand where the approach is practical and what tooling or bindings it would require.
